02 · PROBLEM

Kenapa REST API Aja Nggak Cukup?

❌ REST API + Polling
  • Device kirim POST tiap N detik (boros battery)
  • Browser polling tiap detik (boros bandwidth)
  • Header HTTP gede (~500 byte) tiap request
  • Stateless — server gak tau device online/mati
  • Susah scale ke 1000+ device sekaligus
✅ MQTT + Laravel
  • Persistent connection — push saat ada data
  • Header cuma 2 byte — efisien banget
  • Last Will tau device disconnect mendadak
  • Topic-based routing — broker yang ngurus
  • 1 broker bisa handle 100k+ koneksi

05 · TOPIC

Topic — Alamat Pesan MQTT

Topic itu kayak channel YouTube — publisher upload ke channel, subscriber follow channel. Format hierarki pakai /.

rumah/ruangtamu/lampuLampu di ruang tamu
pabrik/lini-1/mesin/suhuSuhu mesin di lini produksi 1
kebun/+/kelembapan+ = wildcard 1 level (semua kebun)
gedung/## = wildcard multi level (semua di bawah gedung)
💡 Pro Tips
  • Pakai huruf kecil, hindari spasi & karakter spesial
  • Mulai dari general → spesifik (kayak path file)
  • Jangan pakai / di awal — bikin "empty level"
06 · QoS

Quality of Service — Jaminan Pengiriman

QoS 0
At Most Once
Fire and forget. Pesan dikirim sekali, nggak ada konfirmasi. Mungkin hilang.
Use case: data sensor yang sering update (suhu tiap detik)
QoS 1
At Least Once
Ada konfirmasi (PUBACK). Pesan dijamin sampai, tapi bisa duplikat.
Use case: notifikasi penting yang boleh muncul 2x
QoS 2
Exactly Once
4-way handshake. Pesan dijamin sampai tepat 1 kali. Paling lambat.
Use case: transaksi pembayaran, command kritis
07 · FITUR

Fitur MQTT Yang Wajib Tau

📌

Retained Message

Broker simpan pesan terakhir di topic. Subscriber baru langsung dapat nilai terbaru tanpa nunggu publish baru.

⚰️

Last Will (LWT)

Pesan otomatis dipublish kalau client disconnect mendadak. Buat deteksi device offline.

💓

Keep Alive

Client kirim PINGREQ tiap N detik. Broker tau client masih hidup atau udah putus.

🧹

Clean Session

Atur apakah broker simpan subscription & pesan saat client offline, atau reset tiap reconnect.

09 · SETUP

Install & Konfigurasi

# 1. Bikin project Laravel baru
composer create-project laravel/laravel iot-mqtt-app
cd iot-mqtt-app

# 2. Install MQTT client package
composer require php-mqtt/laravel-client
php artisan vendor:publish --provider="PhpMqtt\Client\MqttClientServiceProvider" --tag="config"

# 3. Install Reverb buat broadcast real-time ke browser
php artisan install:broadcasting

# 4. Install Mosquitto broker (Ubuntu)
sudo apt install mosquitto mosquitto-clients
sudo systemctl enable --now mosquitto

# 5. Set MQTT config di .env
MQTT_HOST=localhost
MQTT_PORT=1883
MQTT_AUTH_USERNAME=null
MQTT_AUTH_PASSWORD=null
10 · KODE

Publisher: Artisan Command

// app/Console/Commands/PublishSensor.php
namespace App\Console\Commands;

use Illuminate\Console\Command;
use PhpMqtt\Client\Facades\MQTT;

class PublishSensor extends Command
{
    protected $signature = 'mqtt:publish-sensor';

    public function handle()
    {
        $mqtt = MQTT::connection();
        $payload = json_encode([
            'suhu' => rand(25, 35),
            'kelembapan' => rand(60, 90),
            'waktu' => now()->toIso8601String(),
        ]);
        $mqtt->publish('kebun/zona-1/sensor', $payload, qos: 1, retain: true);
        $this->info("📤 Publish: $payload");
    }
}
11 · KODE

Subscriber: Long-Running Listener

// app/Console/Commands/ListenSensor.php
use PhpMqtt\Client\Facades\MQTT;
use App\Models\SensorReading;
use App\Events\SensorUpdated;

class ListenSensor extends Command
{
    protected $signature = 'mqtt:listen';

    public function handle()
    {
        $mqtt = MQTT::connection();
        $mqtt->subscribe('kebun/+/sensor', function ($topic, $message) {
            $data = json_decode($message, true);
            $reading = SensorReading::create([
                'topic' => $topic,
                'suhu' => $data['suhu'],
                'kelembapan' => $data['kelembapan'],
            ]);
            broadcast(new SensorUpdated($reading));
        }, qos: 1);
        $mqtt->loop(true);
    }
}
12 · KODE

Broadcast ke Browser via Reverb

// app/Events/SensorUpdated.php — broadcast event
class SensorUpdated implements ShouldBroadcast
{
    public function __construct(public SensorReading $reading) {}

    public function broadcastOn(): array
    {
        return [new Channel('sensor')];
    }
}

// resources/js/dashboard.js — listen di browser
import Echo from 'laravel-echo';
Echo.channel('sensor')
    .listen('SensorUpdated', (e) => {
        document.getElementById('suhu').textContent = `${e.reading.suhu}°C`;
        document.getElementById('kelembapan').textContent = `${e.reading.kelembapan}%`;
    });
13 · ALUR

Alur End-to-End Laravel + MQTT

  1. ESP32 + sensor DHT22 baca suhu & kelembapan

14 · SECURITY

Keamanan MQTT

🔐

TLS / SSL

Pakai mqtts:// (port 8883). Set MQTT_AUTH_TLS_ENABLED=true di Laravel .env.

🆔

Username & Password

Auth dasar via CONNECT packet. Set di Mosquitto password_file + Laravel .env.

📜

Client Certificate

Auth via X.509 certificate. Tiap device punya cert unik — paling aman buat produksi.

🚫

ACL (Access Control)

File mosquitto.acl atur siapa boleh pub/sub topic mana. Cegah cross-tenant.

16 · PITFALL

Kesalahan yang Sering Terjadi

  • ❌ Jalanin mqtt:listen via php artisan doang — proses bakal mati. Wajib pakai Supervisor biar auto-restart.
  • ❌ Memory leak di subscriber — Eloquent cache hasil query. Tambahin DB::flushQueryLog() tiap N pesan.
  • ❌ Client ID duplikat — broker disconnect yang lama. Pakai uniqid() atau hostname per client.
  • ❌ Pakai broker public buat data sensitif — broker.hivemq.com publik, semua orang bisa subscribe.
  • ❌ Lupa setting QoS — default 0, command kritis bisa hilang tanpa kamu sadar.
  • ❌ Publish JSON gede-gede — MQTT didesain buat payload kecil, kalau perlu file pakai HTTP/S3.
